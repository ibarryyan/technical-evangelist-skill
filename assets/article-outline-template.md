# Article Outline

```
# <Title — a claim or a named tension>

## Opening
<The concrete failure, reframe, question, or sourced number. 1–2 paragraphs.>

## <Section 1 — the problem, in the reader's terms>
<Why this is worth their time. Why the current approach falls short —
demonstrated, not asserted.>

## <Section 2 — background / context>
<Only what is needed to follow the mechanism. Cut ruthlessly here.>

## <Section 3 — the mechanism>
<The core of the piece. Most of the words live here. One idea per paragraph,
alternating abstraction with something concrete.>

## <Section 4 — practice>
<How it is used. A real example with real output.>

## <Section 5 — trade-offs and boundaries>
<What it improves. What it makes harder. Use it when ___; do not use it when ___.>

## Takeaway
<Thesis, restated harder — or the next action the reader can take today.>
```

## Per-section checklist

- [ ] Section serves the thesis; deleting it would weaken the argument
- [ ] Headings alone read as a coherent argument
- [ ] Claims tagged `[FACT]` / `[INFERENCE]` / `[OPINION]` / `[UNVERIFIED]`
- [ ] Versions pinned for any behavioural claim
- [ ] At least one concrete detail per conceptual paragraph
- [ ] Code samples minimal, runnable, idiomatic, version-pinned
- [ ] Diagrams labelled on the edges, one question each
- [ ] No banned phrases (see `SKILL.md`)

## Titles — deliver three, ranked

1. <claim or tension>
2. <angle 2>
3. <angle 3>

Avoid: "A Deep Dive into", "Everything you need to know", stacked colons,
and any promise the article does not keep.
